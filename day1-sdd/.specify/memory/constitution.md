# 개인 학습용 Todo 앱 프로젝트 헌법

## 핵심 원칙

### I. 단순성을 최우선으로 한다
코드는 가능한 한 단순하게 유지한다. 불필요한 추상화, 외부 라이브러리, 프레임워크는 사용하지 않는다. 기능을 구현할 때는 읽기 쉽고 유지보수하기 쉬운 순수 HTML, CSS, JavaScript 구조를 우선한다.

### II. 모든 기능은 스펙 문서 기반으로 구현한다
새로운 기능, 변경, 버그 수정은 먼저 스펙 문서로 정의하고 검증한 뒤 구현한다. 스펙 문서에 명시된 요구 사항과 사용자 흐름에 따라 구현을 진행하며, 스펙과 다른 동작은 별도 기록 없이 도입하지 않는다.

### III. 프레임워크 없는 순수 웹 구현
정적 웹 앱의 구현은 프레임워크 없이 순수 HTML/CSS/JavaScript로 한다. 빌드 도구, 번들러, 외부 UI 라이브러리, 프레임워크 사용을 금지한다.

### IV. 변경 사항은 반드시 커밋으로 기록
모든 코드 변경, 스펙 수정, 헌법 개정은 커밋으로 기록한다. 커밋 메시지는 변경 목적과 핵심 내용을 명확하게 설명해야 한다.

## 기술 및 제약
- 브라우저 기본 기능만 사용하며, 별도 서버나 백엔드를 요구하지 않는다.
- 상태 저장은 로컬 스토리지 등 브라우저 내장 저장소를 활용한 단순한 방식으로 처리한다.
- UI는 접근성을 고려하고, 과도한 애니메이션이나 복잡한 시각 효과를 피한다.
- 기능 구현은 최소한의 코드로 직관적인 사용자 경험을 제공하는 방향으로 설계한다.

## 개발 워크플로우
- 스펙 작성 → 구현 → 동작 확인 → 커밋
- 모든 변경 전에는 관련 스펙을 기록하고, 변경 후에는 커밋과 함께 변경 사항을 보존한다.
- 스펙과 헌법 간 불일치가 발견되면 헌법을 우선으로 해석하고 필요한 경우 스펙을 수정한다.

## 거버넌스
이 헌법은 프로젝트 개발의 최우선 규칙이다. 헌법과 스펙 간 충돌이 있을 때는 헌법을 우선 적용하며, 필요한 경우 스펙 문서를 개정한다. 헌법 자체 변경은 문서화된 개정으로만 수행하고, 변경일과 버전을 함께 기록한다.
