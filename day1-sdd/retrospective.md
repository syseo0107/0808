# 바이브코딩 vs SDD 비교 회고 (1일차)

## 바이브코딩 경험
- 아이디어를 바로 말하면 즉시 결과가 나와서 빠르고 재미있었다
- 다만 기능을 4번 추가하는 동안 전체 그림 없이 진행되어 상태 추적이 어려웠다

## SDD 경험
- constitution → spec → plan → tasks → implement 단계를 거치니 더 체계적이고 섬세하게 코딩할 수 있어 편리했다
- 스펙 문서가 그대로 테스트 체크리스트가 되어 완성 여부를 스스로 검증할 수 있었다

## 깨달은 점
- 스펙에는 What/Why만 적고 How는 적지 않는다는 원칙 덕분에, 기술 선택을 계획 단계에서 명시적으로 검토할 수 있었다

## 나의 사용 기준
- 일회성 실험/프로토타입: 바이브코딩
- 유지보수하며 키워갈 프로젝트: SDD
