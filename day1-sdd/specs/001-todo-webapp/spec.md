# Feature Specification: Todo 웹앱

**Feature Branch**: `001-todo-webapp`

**Created**: 2026-08-08

**Status**: Draft

**Input**: User description: "오늘의 할일을 관리하는 개인용 Todo 웹앱을 만든다. 사용자는 할일을 추가, 완료 체크, 삭제할 수 있다. 할일에는 마감일을 설정할 수 있고, 마감일이 가까운 순서로 자동 정렬된다. 다크 모드를 켜고 끌 수 있다. 새로고침해도 할일 목록이 유지된다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 할 일 추가 및 관리 (Priority: P1)

사용자는 새로운 할 일을 입력하고 저장할 수 있다. 저장된 할 일은 목록에 표시되고, 마감일이 가까운 순서로 자동 정렬된다.

**Why this priority**: 기본 Todo 앱 핵심 기능이며, 사용자에게 즉각적인 가치 제공.

**Independent Test**: 할 일을 입력하고 등록한 뒤 목록에서 해당 항목이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 앱을 처음 열었을 때, **When** 사용자가 할 일을 텍스트 입력하고 등록 버튼을 클릭하면, **Then** 새 할 일이 목록에 추가된다.
2. **Given** 여러 할 일이 존재할 때, **When** 할 일의 마감일을 지정하면, **Then** 마감일이 빠른 항목이 먼저 표시된다.

---

### User Story 2 - 완료 체크 및 삭제 (Priority: P2)

사용자는 할 일 항목을 완료 표시하거나 삭제할 수 있다. 완료된 항목은 체크 상태가 표시되고, 삭제 버튼으로 항목을 제거할 수 있다.

**Why this priority**: 사용자가 Todo 앱을 실제로 관리하기 위해 필수적인 상호작용.

**Independent Test**: 항목을 완료 처리하거나 삭제할 수 있어야 한다.

**Acceptance Scenarios**:

1. **Given** 할 일이 목록에 있을 때, **When** 사용자가 항목의 체크박스를 클릭하면, **Then** 해당 항목이 완료 상태로 표시된다.
2. **Given** 할 일이 목록에 있을 때, **When** 사용자가 항목의 삭제 버튼을 클릭하면, **Then** 해당 항목이 목록에서 제거된다.

---

### User Story 3 - 다크 모드 토글 (Priority: P3)

사용자는 다크 모드를 켜고 끌 수 있다. 선택한 모드는 즉시 반영되며, 새로고침 후에도 유지된다.

**Why this priority**: 사용자 환경 개선을 위해 필요하지만, 핵심 할 일 관리 기능보다 우선순위가 낮다.

**Independent Test**: 다크 모드를 켜고 끌 수 있으며, 상태가 유지된다.

**Acceptance Scenarios**:

1. **Given** 기본 화면이 표시될 때, **When** 사용자가 다크 모드 버튼을 클릭하면, **Then** 페이지 색상이 다크 모드로 전환된다.
2. **Given** 다크 모드를 활성화한 상태에서, **When** 페이지를 새로고침하면, **Then** 다크 모드 설정이 유지된다.

---

### Edge Cases

- 입력된 할 일 텍스트가 비어 있거나 공백인 경우, 항목이 생성되지 않아야 한다.
- 동일한 할 일 텍스트가 여러 번 입력된 경우, 중복 허용 여부는 스펙상 제한하지 않으며 중복 항목이 그대로 저장된다.
- 마감일이 지정되지 않은 항목은 마감일 있는 항목 뒤에 표시된다.
- 과거 마감일로 설정된 항목은 정상적으로 목록에 표시되지만, 시각적으로 구분되는 표시가 있을 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 새 할 일을 텍스트 입력으로 추가할 수 있어야 한다.
- **FR-002**: 사용자는 각 할 일에 마감일을 선택할 수 있어야 한다.
- **FR-003**: 할 일 목록은 마감일이 가까운 순서로 자동 정렬되어야 한다.
- **FR-004**: 사용자는 할 일을 완료 표시할 수 있어야 한다.
- **FR-005**: 사용자는 할 일을 삭제할 수 있어야 한다.
- **FR-006**: 사용자는 다크 모드를 켜고 끌 수 있어야 한다.
- **FR-007**: 새로고침해도 할 일 목록과 다크 모드 설정이 유지되어야 한다.
- **FR-008**: 앱은 순수 HTML/CSS/JavaScript로 구현되어야 하며, 프레임워크를 사용하지 않아야 한다.
- **FR-009**: 상태는 브라우저 로컬 스토리지에 저장되어야 한다.

### Key Entities

- **TodoItem**: 사용자 할 일 항목.
  - `id`: 고유 ID
  - `text`: 할 일 내용
  - `dueDate`: 마감일 (선택 사항)
  - `completed`: 완료 상태
- **UserPreference**: UI 설정
  - `theme`: `light` 또는 `dark`

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 할 일을 추가하면 목록에 즉시 표시된다.
- **SC-002**: 마감일이 빠른 항목이 목록 상단에 표시된다.
- **SC-003**: 완료 체크 또는 삭제 후 화면이 즉시 갱신된다.
- **SC-004**: 새로고침 이후에도 저장된 할 일이 유지된다.
- **SC-005**: 다크 모드 선택이 새로고침 후에도 유지된다.

## Assumptions

- 모바일 반응형은 우선순위 낮음; 우선 데스크톱/태블릿 수준의 기본 레이아웃을 지원한다.
- 로그인, 계정, 서버 저장소는 범위에 포함되지 않는다.
- 브라우저 로컬 스토리지를 사용할 수 있다.
- 사용자는 최신 모던 브라우저에서 앱을 실행한다.
